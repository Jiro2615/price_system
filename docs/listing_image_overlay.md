# 出品画像のロゴ・送料無料合成

店舗設定で明示的に有効にした店舗の実出品で、ダウンロード後・検証とアップロード前に先頭画像だけ合成します。全店舗で初期値はオフです。サブ画像は変更しません。アップロードしたロゴを指定した横幅比率で左上に配置し、縦横比を保持します。極端に縦長の場合は画像内に収まるよう縮小します。JPEG再保存による圧縮は発生します。

店舗設定で「右下の送料無料」をオンにし、全SKUの `shipping.postageIncluded` が boolean `true` の場合だけ送料無料を表示します。不明・有料SKU混在の場合はロゴのみです。必要資産やPillowがない場合、加工対象画像は失敗となり画像アップロードに進みません。

## 導入

実行PCでコードと `assets/listing_overlay/` を反映し、リポジトリ直下で `py -3.12 -m pip install -r requirements.txt` を実施してください。既に動いているワーカーへの即時反映はありません。ジョブ停止・アイドル確認後、通常の手順でワーカーを再起動してください。本機能の追加作業では本番反映・再起動・実出品は行っていません。

店舗設定で「出品画像の加工」を「ロゴを付ける」にし、2MB以内・1600万画素以内の静止PNG/JPEG/WebPを選択してSave to DBしてください。ロゴ横幅は5～50%（初期27%）。ロゴは最大1200pxのPNGに正規化し共有DBの既存JSON設定に保存するため、PCごとのファイル配置やDBマイグレーションは不要です。オフで保存しても登録ロゴは保持します。新画像を選択しなければ保存済み画像を維持します。

ワーカー起動環境の `LISTING_IMAGE_OVERLAY=0` でも強制無効化できます。設定は出品準備時にジョブへ保存されるため、設定変更後に新しく準備する出品から適用します。画像アップロード済みからの再開は既存URLを再利用するため合成をやり直しません。Web Orchestrator側にもPillowの導入が必要です。

## 保存とローカル確認

v3では送料無料バッジの角丸外側を透過PNGにし、合成時もアルファを保持します。角の外には商品画像が見えます。最終商品画像はJPEGで、左上ロゴの白背景は従来通り保持します。

送料無料バッジは約40%幅・12%高さ以内、端の余白は0.5%で配置します。ロゴ素材内の白余白は保持し、縦横比は変えません。大きい商品画像でも同じ比率になるよう拡大縮小します。

元のダウンロード画像は変更しません。合成画像は出力ルートの `_listing_overlay/<元画像・資産・設定のハッシュ>/` に別保存します。再試行は常に元画像から合成し、二重貼り付けを避けます。実行結果の `download_result.image_overlay` に元画像・加工画像のパスと表示条件を残します。

```powershell
py -3.12 -m scripts.preview_listing_overlay 'C:\path\original.jpg' --free-shipping
```

複数の元画像パスも指定可能です。`output/overlay_preview/preview_manifest.json` にプレビュー一覧が出ます。これはローカル処理のみで、API通信・アップロード・DB更新はありません。送料が確認できない画像には `--free-shipping` を指定しないでください。

## 既存商品

この変更だけでは既存商品を更新しません。既存商品の全件取得・一括アップロード・画像URL差替え機能はまだありません。実施する場合は店舗と対象商品を確定し、現在の画像URL一覧を保存してから、元画像でプレビューし、新しいR-Cabinetファイル名へアップロードして画像のみを変更する別工程を用意します。既存URLへの上書きは避けます。

楽天の画像ガイドラインには文字・ロゴ面積などの条件があります。元画像の表現も含め、RMS側の画像判定で確認してください。合成処理はガイドライン適合を保証しません。
