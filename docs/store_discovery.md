# Amazon関連店舗の収集（単独PC）

QNAP上の処理・Chrome・楽天APIは使用しません。共有DBからの読み取りを選ぶ場合は、そのDBへのネットワーク接続と既存の `.env` が必要です。DB変更・出品は行いません。

## 実行

`C:\rakuten\price_system_listing` に今回のファイルと既存コードを置きます。別の配置ならパスを読み替えてください。

```powershell
Set-Location C:\rakuten\price_system_listing
py -3.12 -m pip install requests beautifulsoup4 "psycopg[binary]" python-dotenv
py -3.12 scripts\discover_amazon_stores.py --store rakuten_1 --seed-limit 100 --max-stores 20 --exclude-shop ecprime500 --exclude-shop lifeforest --output-dir output\store_discovery_trial
```

この段階では検索せず、DBから検索元を準備し `state.json` に保存します。まず検索語を確認してください。DB設定は既存の `scripts/db_config.py` を利用し、リポジトリの一つ上の `.env` を読みます。

公開ページの読み取りを開始する場合のみ `--execute` を追加します。

```powershell
py -3.12 scripts\discover_amazon_stores.py --store rakuten_1 --seed-limit 100 --max-stores 20 --exclude-shop ecprime500 --exclude-shop lifeforest --output-dir output\store_discovery_trial --execute
```

まず20店舗で出力項目と判定を目視確認してください。その後、同じコマンドの `--max-stores` を300などへ増やすと続行できます。

候補100店舗を目標に継続する場合は `--max-stores 10000 --target-candidates 100` を指定します。確認件数ではなく候補数で停止します。保存済み検索語を順次処理し、検索語を使い切った場合やアクセス制限時にも停止します。100店舗の発見を保証するものではありません。

自分で用意した検索語を使う場合は `--keywords C:\path\keywords.txt`（UTF-8・1行1検索語）を追加します。この場合DB接続は不要です。再開時も同じ引数を指定します。

自店舗はDBに登録された `rakuten_item_url` の店舗部分から除外します。URL未登録の店舗は自動判別できないので `--exclude-shop 店舗URLの店舗部分` を指定してください（複数指定可）。除外指定はチェックポイントにも保存されます。上記コマンドは店舗1・2を両方除外します。

## 出力と再開

「評価数」は店舗レビューリンク内の件数です。新規候補だけで取得し、取得済み店舗は再取得せず空欄のまま保持します。追加の通信はありません。件数が取得できない場合も空欄とし、0件と区別します。503待機中の更新再起動では `--startup-delay 秒数` で通信再開を遅らせられます。

- `output\store_discovery_trial\stores.tsv`：UTF-8 BOM付き。候補店舗だけを出力。
- 列：店舗名、評価、出品数、店舗紹介文、店舗URL、店舗ID、判定、判定根拠、確認商品URL、検索語、取得日時、未取得項目。
- `state.json`：検索元、完了した検索、発見した店舗、判定済み店舗を保存。削除しなければ同じコマンドで続行。取得途中の店舗は再試行。IDや先頭商品を取得できない特殊形式は `errors` に保存し、候補外と断定せず次へ進みます。再試行する場合は `--retry-errors` を追加してください。
- Ctrl+Cで停止できます（通常の通信は最大30秒のタイムアウト）。TSVをExcel等で開きっぱなしにすると保存に失敗する場合があるため閉じて実行してください。
- 同じ出力フォルダで同時に複数プロセスを起動しないでください。新規調査は別フォルダを使用します。
- 403/429やアクセス確認画面、取得形式不明時は中止。解除後に手動再実行。回避処理はありません。500/502/504は待機して最大2回再試行します。503のみ5分→10分→20分→以後30分間隔で同じ要求を自動再試行します（回数制限なし）。Retry-Afterがそれより長ければ指定時間を優先します。待機中は進捗件数が変わりません。中止する場合はCtrl+C。プロセス終了後の自動起動ではなく、稼働プロセス内の再試行です。

## 判定と取得範囲

自店舗の有効な出品レコードから、Amazon商品名（なければ楽天商品名）を選びます。DBにブランド・ジャンルが保存されている場合は組合せごとに交互に選択。欠損している場合の分散は保証しません。検索語はまず商品名そのままを使います。長すぎる・販売文言が多い場合はキーワードファイルで調整してください。

各検索の先頭1ページが既定です。`--pages` は最大10。発見した商品から店舗IDを確認後、その店舗の商品一覧のHTML掲載順で、同店舗に属する先頭商品を選びます。既存ASIN抽出のAmazon関連語判定を流用します。対象候補でもAmazon仕入れの証明ではありません。先頭商品に関連語がない店舗は見逃します。

店舗名・店舗評価・紹介文は店舗内検索のショップヘッダーから取得します。商品評価は使用しません。出品数は「検索結果1〜45件（N件）」の合計N件（検索時点で表示される件数で、RMS管理商品数ではありません）です。紹介文はショップヘッダーの店舗固有の短い紹介文で、会社概要全文ではありません。未対応のHTML形式は空欄＋未取得項目として出力し、推測で補完しません。ECプライムの実HTMLで4項目を確認済みです。

`--snowball --products-per-shop 8` で候補店舗の商品から再帰的に検索を広げます。候補店舗の取得済み先頭一覧から最大8商品を分散選択し、商品URLと正規化した検索語で重複除外します。既存候補のみ初回に一覧を再取得します。候補店舗由来の検索3回に対して自店舗由来を1回混ぜます。追加検索語は最大1000個。商品名が取れない商品は追加しません。

TSVの「検索元」「検索元店舗」と `state.json` の `source_stats` に、導入後の検索回数・判定成功店舗数・候補数を記録します。店舗は最初に発見した検索元に帰属します（過去分は集計対象外）。ヒット率の向上は未保証です。404/410は店舗を未判定として保存し続行します。503は上記の自動再試行、それ以外は既定の再試行を使い切るかアクセス制限時に停止します。
