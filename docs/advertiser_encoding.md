# 広告文責の会社名が文字化けする場合

広告文責の会社名はAmazonや他店舗から転載せず、実行PCの共有設定 `C:\rakuten\.env` の `RAKUTEN_2_COMPLIANCE_ADVERTISER_NAME` 等から作成します。通常出品・条件無視ASIN出品は同じ処理です。化粧品等の同一JAN証跡を取得できた場合に追記するため、以前は追記の対象にならず、設定の不具合が表面化しなかった可能性があります。

2026-10-07の調査では、担当 `keypc` の設定自体が文字化けしていることを利用者が確認しました。同日の店舗2の保存済み出品スナップショット281件に、同じ崩れた会社名がありました。これは当時の送信記録であり、現在のRMS本文が未修正という意味ではありません。直前の2026-10-02～10-06の400件では広告文責の追記は確認できませんでした。設定が壊れた日時や編集操作そのものは、履歴がないため断定できません。

## 修正した処理

- 広告文責の設定は `.env` を `utf-8-sig` で直接読み、現在のファイル値を優先します。親プロセスの古い値や、他の設定のグローバルな上書きに依存しません。
- 明示的な空欄は空欄のまま扱います。設定キーがない場合だけ環境変数を参照します。
- 明らかなUTF-8/CP932の取り違え、置換文字・制御文字を広告文責の会社名に検出したら設定エラーとして止めます。会社名を推測して復元せず、条件無視の「証跡不足」として通しません。
- 古いPCで作成済みの出品データも、画像アップロード・商品登録前に確認します。手直し済みの既存商品を自動更新する機能ではありません。

## 担当PCでの確認

1. `C:\rakuten\.env` の会社名設定を確認し、正しい表記に直してUTF-8で保存します。APIキー等の他の行は変更しません。
2. Git更新後、読み取りだけの診断を実行します。

```powershell
py -3.12 -X utf8 C:\rakuten\price_system_listing\scripts\diagnose_listing_advertiser.py --store rakuten_2
```

`status=configured` と会社名を確認します。電話番号の値・認証情報は出力しません。新しい判定で生成し直したデータを使います。古い文字化け入りのJSONはそのまま再実行できません。稼働中ジョブを強制再起動せず、終了・停止を確認してから更新します。

## 回帰テスト

`tests/test_advertiser_encoding.py` は一時的な設定ファイルとモックだけを使用します。`tests/run_marketplace_regression.py` の外部DB/HTTP禁止ガード下で実行します。
