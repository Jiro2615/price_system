# 条件無視出品の会社 ブランド除外と要確認語

条件無視ASIN出品の「禁止語を無視」とは別に、次の2設定を選べます。新しい画面では両方ON、以前のジョブ・通常出品では追加判定OFFです。

- 禁止会社・ブランドを除外する：確認した分類表の「会社名と警告由来」「ブランド等の候補」を単語一致で除外します。
- 要確認語を警告にして出品を保留する：「要確認語」に単語一致した商品は未出品のまま保存します。「一般表現等」はこの追加判定の対象外です。

分類は `reference/listing_policy/forced_word_groups.json` の2026-10-07版を使用し、現在有効な楽天用禁止語マスターに含まれる語だけを判定します。追加された未分類の禁止語は要確認扱いです。共有の禁止語DBを無効化・削除する機能ではありません。

## 単語としての一致

HTMLを除いて全角・半角と英字大小を揃え、前後に文字・数字・長音記号が連続する部分一致を除きます。例えば `Count` 内の `OU`、「ハイライト」内の「イラ」は対象外です。日本語が連続して単語の区切りを確定できない場合、本文の部分一致だけでは決めません。ブランド・メーカー欄では、株式会社等の法人表記を除いた名称全体の一致も使用します。無関係な長い名前の一部分を一致としません。

分類モードがONの場合、会社・ブランド名と要確認語は新しい2設定だけで判定します。従来の部分一致判定や空白挿入ルールがこれらの語を先にブロックすることはありません。一般表現を無視しない場合は、一般表現側の従来の判定を残します。追加判定を両方OFFにすると従来の条件無視出品に戻ります。通常出品の判定は変更しません。

## 要確認の商品

ASIN・商品名・一致語・該当項目・前後の文脈を結果一覧に表示します。要確認語だけのCSVも保存できます。画像アップロード・商品登録・在庫登録は行いません。

確認後は1商品ずつ「確認して出品」を押し、実出品の確認に同意します。元の店舗・判定条件・担当PCを引き継いだ出品ジョブを作成します。連打や通信再試行では同じ承認に対するジョブを再利用し、2件目を作りません。同じ店舗の出品処理が稼働中なら待機します。

保存した商品情報を使用してASIN再入力やKeepaの重複取得を省きます。承認後もAmazonの価格・在庫・配送・ギフト、現在のDBルール、重複出品、属性・実送信前の確認は維持します。Keepa情報が24時間を超えた場合は再取得します。新しい一致語・商品名・文脈・店舗・分類バージョンへの変更は以前の承認では通しません。会社・ブランド除外は要確認語の承認で解除できません。

保存データは既存の `listing_run_item_results.result_json` に保持し、一覧APIでは重い商品キャッシュを返しません。新しいDBテーブルは不要です。出品時の認証設定は保持せず、現在の設定で取得します。保存内容がない場合は再判定が必要です。

## 反映と検証

Web Orchestratorと出品担当PCの両方を更新してください。新モードは専用の `listing_forced_word_execute` ジョブ種別を使用し、旧エージェントの管理対象一覧にないため実行を拒否します。出品プログラムだけ古い場合は新しい引数を認識せず停止するため、設定を黙って無視して出品しません。出品PCを先に更新し、QNAP反映後に新モードを開始します。稼働中のジョブを強制再起動しないでください。

`tests/test_forced_word_policy.py` と Web Orchestrator の `tests/test_forced_word_review.py`・`tests/test_forced_word_review_ui.cjs` はモック／外部接続なしで検証します。実出品や承認ジョブの起動は別の明示的な操作です。
