# 既出品の内容最新化

`--update-existing`（Webの単品・一括最新化）は新規出品とは別のモードです。

- 有効な既出品の管理番号を再利用します。対象がない場合や販売停止・削除対象は新規出品へ切り替えません。
- 90日平均出品者数、過去NG、ブラックリスト、禁止会社・ブランド、禁止語・要確認語、カテゴリ除外、成人・電子版、楽天複数店舗数などの出品可否判定は省略します。
- Amazonの価格・在庫・ギフト・配送条件も最新化の出品可否条件にはしません。取得値を架空の合格値へ置き換えることはありません。
- タイトル・説明の文言変換、書籍形式の注記、証跡が得られた場合の広告文責等の生成、API用の文字正規化は維持します。
- Amazonの要求ASIN・ページASIN、取得したKeepaのASINが対象と一致することを確認します。ASIN不一致・未確認、取得エラー・確認待ちは停止します。送信前にも保存した実観測を確認します。
- 画像・本文・ジャンル・API形式など更新データの成立条件は維持します。未取得の必須属性は従来の条件無視出品と同じ `-` 表記を使用します。JANがないことだけでは止めません。
- 販売価格は既出品のDB値を使用し、価格を再計算しません。既出品の販売価格が不明なら停止します。在庫APIを呼ばず、DBへの同期でも価格・在庫・停止設定は変更しません。

準備結果には `content_refresh: true` と判定省略の説明を保存します。旧バージョンの準備結果は再取得が必要です。通常出品・条件無視ASIN出品の条件には影響しません。

検証は `tests/test_content_refresh_policy.py` および `tests/test_listing_batch_fast_pipeline.py` の模擬テストで行えます。実際の最新化や出品を検証目的で実行しないでください。
